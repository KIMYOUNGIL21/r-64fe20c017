4. ④ 수노 음원 생성 NEW 2026-07-29

무슨 일: 예전엔 사장님이 수노에서 직접 곡을 뽑아야 했다. 이제 총괄PD가 브라우저 자동화로 작업판에 이미 있는 가사·스타일·Exclude를 그대로 옮겨 넣어 곡을 뽑고, 나온 두 버전을 실측 비교해 하나를 고른다. 사장님이 옆에서 지켜보는 걸 전제로 진행 — 수노 웹앱 렌더러가 30초+ 멈추거나 세션이 끊기는 일이 잦지만, 끊길 때마다 재접속해서 이어간다.

4-1. 보이스 장착

수노 Create → 고급(Advanced) 모드 → + 보이스 → 채널 이름으로 검색 → 장착. 페이지를 새로 열면 보이스가 풀리므로 곡마다 재확인해야 한다. (표 = 위 "채널 3개 비교" 참고)

4-2. 곡마다 입력하는 4칸

칸어디서 가져오나비고
가사작업판의 lyrics 필드구조 태그 포함 그대로: [Chorus - half strength, lone piano] [Verse 1 - hushed] [Bridge] [Guitar Solo] 등. 이 태그가 곡의 빌드업 설계(숨죽인 벌스→파이널 폭발)를 수노에 지시한다.
스타일작업판의 style 필드900자 안팎, 장르·BPM·악기·보컬 질감·곡 전개(Starts~/Verse~/Chorus~/Bridge~/Final chorus~)까지 문장으로 서술
Exclude작업판의 excl 필드공용 베이스(관중소리·합창·랩·EDM·남성보컬·트로트 등) + 채널별 추가(록 계열은 heavy metal·upbeat dance beat 추가)
제목작업판의 title그대로 입력 후 만들기 → 2버전 동시 생성

4-3. A/B 판정 — 에너지 곡선 실측

두 버전 다 MP3 다운로드 → ffmpeg로 rms→dB 추출 → 0.5초 창 10구간 평균 곡선 + 피크 시점 + 파이널 구간 리프트(뒤 25% 평균 − 중간 25% 평균)를 계산한다. 곡 설계 의도(숨죽인 벌스→파이널 코러스 폭발)에 맞는 쪽, 즉 피크가 후반부(80%+)에 있고 파이널 리프트가 양수/근접한 쪽을 고른다.

실측 원리 (파이썬) raw = ffmpeg -i <파일> -f f32le -ac 1 -ar 22050 - # PCM 추출
rms = sqrt(mean(y[창]**2)) → db = 20*log10(rms) # 0.5초 창마다
curve = 10구간 평균 / peak_t = argmax(rms)*0.5 # 곡선 모양 + 피크 시점
final_lift = mean(db[뒤25%]) - mean(db[중간25%]) # 파이널이 진짜 터졌는지
길이가 6분을 넘으면 구조가 늘어진 것으로 의심 — 짧은 쪽을 우선 검토한다 (실측 사례: 6:12 vs 4:17 중 4:17 채택).

4-4. 저장

확정본만 채널 작업실 폴더에 번호를 매겨 저장. 탈락본은 폐기하지 않고 같은 폴더 안에 보관(재검토용).

<채널>\<작업실>\<앨범명>\ ├─ 1. 곡제목.mp3 ← 확정 음원 ├─ 1. 곡제목.txt ← 태그 뺀 순수 가사 (song\SRT\ 원본과 동일 내용) ├─ 2. 곡제목.mp3 ├─ 2. 곡제목.txt ├─ ... (곡 수만큼) └─ _후보탈락\ ├─ 곡제목_B.mp3 ← 떨어진 버전 (삭제 아님, 재검토용) └─ ...

전곡 완료되면 사장님께 이 폴더 경로를 알리고 "여기에 썸네일(클린가로·썸네일가로·세로)만 넣어주시면 이어서 진행합니다"로 마무리한다.

5. ⑤ 썸네일 투입 · 재료확인

사장님이 이미지 3종을 위 앨범 폴더(또는 곡별 SRT\)에 넣는다: 클린가로(글자 없음, 영상 배경용) · 썸네일가로(유튜브 썸네일, 2MB 이하) · 세로(쇼츠 배경). 넣고 "재료 확인해"라고 하면:

  1. 곡마다 이미지 3종이 다 있는지 점검. 부족하면 부족분만 짚어 알리고 대기(렌더 진행 금지, 채근하지 않음)
  2. 세로 배경이 없으면 가로에서 만들 수도 있다: python make_vertical.py <가로.png> "SRT\곡제목숏츠.png" --cx 0.51 --montage (인물 얼굴 중심 좌표 지정, --montage로 나온 확인용 이미지를 눈으로 검수)
  3. 다 있으면 그대로 ⑥ 제작으로 자동 진행 — 곡마다 재승인 요청 안 함(가사·음원 단계에서 이미 사장님이 감독했으므로)

6. ⑥ 제작: 타이밍 → 빌드

무슨 일: "가사 자막이 노래에 착착 맞게 뜨는" 비밀이 이 단계. 노래에서 목소리만 분리해 AI가 받아쓰기하고, 원래 가사와 글자를 맞춰 발성 덩어리(구절) 단위로 줄마다 시작 초를 계산한다. 그다음 영상 설계도(HTML)를 만든다.

코드에서는 (song\ 안에서 실행, <slug>=곡의 영문 약칭) ① songs\<slug>.json 매니페스트 — 곡 정보가 전부 이 파일 하나에. 곡마다 새 스크립트 금지, 이 파일만 바꾼다
② python pipe_setup.py <slug> — SRT→assets 복사 + 가사 태그 정리
③ python separate-vocals.py assets\<slug>\<slug>.mp3 assets\<slug>\<slug>-vocals.wav — demucs로 보컬만 분리
④ python align_blocks.py <slug> --write — 표준 정렬기(v3). 무음(숨)으로 끊은 발성 덩어리를 진짜 구절 경계로 보고, 덩어리 하나씩만 whisper 전사 → <slug>.timing.json
⑤ python _check\verify_align.py <slug> · _check\verify_blocks.py <slug> --cuts — 정렬 결과 에너지 검증
⑥ python pipe_build.py <slug> — 롱폼 설계도 <slug>-mvB(-fx).html 생성 (배경사진+자막+구독카드+효과가 코드로 박힘)
⑦ python build_shorts3.py <slug> — 쇼츠 3컷: ffmpeg로 오디오 20초씩 자르고 컷별 설계도 3개 생성
⚠️ 폐기된 방법: pipe_timing.sh(=자동타이밍.py, whisper 곡 전체 1회 전사)는 뒤로 갈수록 밀리는 사고가 나서 쓰지 않는다. 반드시 align_blocks.py(v3)를 쓴다.
쇼츠 3컷 규칙: ①1절 후렴 ②2절 후렴 ③클라이맥스(2절 없으면 ①후렴 ②브릿지→파이널 진입 ③반전 펀치라인). 각 20초 강제 컷이라 펀치라인이 안 잘리게 뒤에서부터 역산해 컷 시작점을 잡는다.

7. ⑦ 검수 게이트 1 — 제작 검수

무슨 일: 굽기 전에 자막 싱크와 쇼츠 규격을 검사. 여기 통과 못 하면 렌더 금지.

코드에서는 ① python 검수.py <slug> c1(/c2/c3) — 구운 자막 시각 vs AI가 다시 들은 시각을 줄 단위 비교 (0.35초 이내 ✅, 0.7초 이내 ⚠️, 그 이상 ❌)
② node validate_short_fx.mjs — 쇼츠 표준 검사: 구독 CTA 위치·길이·상단 채널 타이틀. render_shorts3.sh가 렌더 전에 자동 호출
③ python _check\onset_check.py <slug> 2026-07-19 신설, 전곡 필수 — 위스퍼 없이 몇 초 만에 분리보컬의 에너지 온셋만 실측. 첫 보컬 진입줄·쇼츠 컷 시작줄은 |diff| < 0.35초 필수, 나머지는 |diff| ≥ 0.8초인 줄만 손보정. 결과 txt를 _check\에 물증으로 남긴다
검수.py의 ⚠️/❌는 맹신 금지. 믹스(비트·브라스)를 목소리로 착각하는 오탐이 잦다. _check\blocks_at.py <slug> <t0> <t1>로 그 구간의 실제 발성 덩어리 시작을 보고 자막 = 덩어리시작 + 0.40초면 정상 — 이게 최종 판정 기준이다. 실측 사례: 지적 5건이 전부 오탐이었던 경우도 있음.

15. 철칙 — 사고에서 배운 것

  • 영상 ID는 정확일치만. "최신 영상" 추측으로 잡으면 남의 영상을 재예약하는 사고가 난다 (실제 있었음).
  • 렌더 2개 동시 금지, 렌더 중 업로드 금지. 컴퓨터가 버벅이면 둘 다 망한다.
  • 설명란 AI 고지는 맨 아래 한 줄. 위에 있으면 감성 인트로가 죽는다. 업로더가 자동 교정.
  • 발행 후 댓글 켜짐 확인. 1호 업로드가 댓글 꺼진 채 나간 사고 → 이제 예약 직후 강제 켜짐 + QA 필수 항목.
  • 검수 도구의 ❌는 실측으로 재판정. 신나는 곡·긴 절창에서 오탐 잦음. 최종심은 항상 분리보컬 에너지.
  • 3채널은 복사 이식 — 버그는 같이 가지만 수정은 안 따라온다. 공용 스크립트 고치면 채널_공용파일_대조.py로 다른 채널도 확인. 단, 채널마다 소재 특성이 달라 무조건 역이식하면 오히려 파탄난다(트로트 매처 사례) — 역이식 전 온셋 실측으로 확인.
  • 원곡·유명곡과 겹치는 소재는 웹에서 실제 가사 대조. 기억으로 "자작" 판정 금지 — 놓치면 QA가 나중에 적발.
  • QA 성적표 없이 "발매 완료" 보고 금지.
  • 수노 자동화는 끊겨도 밀고 나간다. 30초+ 멈춤·세션 끊김은 정상 범위 — 재접속해서 계속. 크레딧/한도 걸리면 사장님께 상황만 보고.
